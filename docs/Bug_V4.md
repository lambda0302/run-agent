## 发布流程：`--version` 测试硬编码版本号（V4-1）

- **现象**：0.4.0 bump 后推送，CI 首跑挂——`tests/cli.test.ts` 里 `--version` 用例断言的是**硬编码的字符串 `"0.3.2"`**，而 `dist/cli.js --version` 已输出 `0.4.0`。
- **根因**：测试把"当前版本"写死，本地全量测试只在 bump **之前**跑过；bump 后没重跑，等于没人发现断言过期。
- **修复**（commit `a28d7b6`）：`--version` 用例改为读 `package.json` 的 `version`（`pkg.version`）做断言，版本号单一来源，bump 后不再需要手改测试。
- **教训**：版本类断言必须引用 `package.json`，别写死；**每次 bump 版本号后，本地必须重跑全量测试**（只在 bump 前绿等于没验证）。

## 跨平台：macOS `/var` 符号链接使路径断言失效（V4-2）

- **现象**：0.4.1 推送后仅 **macOS × 3 个 Node** 全挂（typecheck/lint 过，`npm run test` 挂），Windows/Linux 全绿。
- **根因**：macOS 的 `TMPDIR=/var` 是指向 `/private/var` 的符号链接。`mkdtempSync` 返回**未解析路径**（`/var/...`），而 `process.cwd()` 返回**解析后路径**（`/private/var/...`）。`verify.test.ts` 用 `mkdtemp` 的返回值拼期望路径，而 `verify.ts` 内部用 `process.cwd()` 取路径——两侧一个是 `/var/...`、一个是 `/private/var/...`，断言必挂。
- **修复**（commit `38c7b3c`）：测试期望值从 `process.cwd()` 反推（`path.resolve(process.cwd(), rel)`），与实现**同一来源取路径**。
- **教训**：① 测试里凡断言"绝对路径"，要跟实现**同一来源**取路径，别用 `mkdtemp` 返回值；macOS 符号链接会打脸。② CI 本地全绿 ≠ 全平台绿，平台专属问题只能靠 CI 矩阵暴露——**每次发布前看一遍 CI 结果，别只看本地**。③ 该教训在 V4.5 白名单设计里直接复用：`pathInCwd`/`pathForms` 两侧都 resolve 后比较，天然兼容 `/var`→`/private/var`。

## 测试稳定性：Windows 并行下 git 类测试偶发超时（V4-3）

- **现象**：并行 + Windows 下，git 类测试（`gitInitRepo` 四步 `execFileSync` + `buildRepoMap` 的 git 调用）单测经常超过 vitest 默认 5s 超时，CI 偶发红。
- **根因**：git 首次调用要初始化配置/索引，Windows 下子进程启动开销大，并行跑时叠加。
- **修复**：`vitest.config.ts` 的 `testTimeout` 提到 `30_000`（git 类测试专用余量，普通测试不受影响）。
- **教训**：依赖外部可执行文件（git 等）的测试要预留充足超时；但**只是缓解**——V4.5 全量跑时 `collectGitContext` 内部单条 git 命令还有 800ms 超时，负载高时仍偶发超限（见 [Bug_V4.5.md](Bug_V4.5.md) V4.5-8）。

## 功能缺口：单轨主动记忆对快模型触发不可靠（V4-4）

- **现象**（真实会话 2026-08-11）：用户与 run-agent 对话中暴露了大量值得沉淀的身份信息（如「25岁/Java 背景/学 Python」），但整场会话 `remember` **从未被调用（0 次）**——单轨主动记忆（主 agent system 指引「发现稳定结论时用 remember」）对 `deepseek-v4-flash` 这类**快模型**触发不可靠。
- **根因**：快模型推理倾向低，system 里的「主动沉淀」指引不足以让它在合适的时机发起 `remember`；依赖主 agent 自觉的单轨机制在低成本模型上命中率不足。
- **对照**：还原 Claude Code 源码，其主动记忆是**双轨**——主 agent 直接写（可选）+ **每轮对话结束后台跑一个记忆提取子 agent**（`extractMemories.ts`：fork 主对话 + 游标增量 + 只读工具集 + 记忆目录写限 + 专门提取 prompt 枚举 `<when_to_save>` 触发场景 + maxTurns 5；主 agent 本轮已写则跳过）。
- **处理**：用户决定维持现状，**后台提取双轨推迟到子 agent 基建成熟后（已记入 Plan.md V7「后台记忆提取子 agent」）**——避免在无子 agent 基建时硬造半套。
- **教训**：跨会话记忆的可靠性不能押在单一模型自觉上；快模型需要"机制兜底"（后台子 agent），慢模型可以靠指引。**触发面按目标模型的能力来设计**。

## 小结

- **真 bug 4 个**：2 个测试/发布流程问题（V4-1 硬编码版本、V4-3 git 超时）、1 个平台专属测试坑（V4-2 macOS 符号链接）、1 个功能缺口（V4-4 单轨记忆触发不可靠）。
- **共性教训**：① 版本断言读 `package.json`；bump 后本地重跑全量。② 断言绝对路径要与实现同源取路径；发布看全平台 CI。③ git 类测试预留超时。④ 跨会话记忆可靠性要有机制兜底，别只靠模型自觉。
- **非产品 bug（不列入表）**：`vitest.config.ts` 的 `testTimeout` 提高属于稳定性缓解而非缺陷修复；0.4.0 的权限/记忆行为本身没有功能性缺陷（192→215 测试全绿）。
